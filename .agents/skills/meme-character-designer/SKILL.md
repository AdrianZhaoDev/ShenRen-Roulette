# 新梗角色设计

## 目标

交付可直接加入项目的角色方案，而不是只有概念。每个角色必须同时具备：

- 唯一 `id`、中文名、称号、emoji、主题色和立绘路径；
- 2 个固定核心被动；
- 至少 2 个普通主动技能；
- 至少 1 个主动究极技，或明确的被动究极技；
- 每个技能的 `effectKind`、伤害、冷却、稀有度、描述和喊话；
- 立绘、GIF/视频、音效的来源、许可证/授权状态和本地文件路径。

## 工作流

1. **确定梗与边界**：写清梗的可识别特征、目标受众、避免攻击现实个人/群体的风险，以及角色在战斗中的一句话定位。
2. **设计战斗 kit**：从现有 `js/data.js` 的字段和 `js/effects.js`/`js/battle.js` 的 `effectKind` 复用实现。不要为了一个角色新增平行系统；新 `effectKind` 必须同时给出处理函数和回归场景。
3. **检查平衡**：普通技能通常使用 3–5 秒冷却、约 90–140 基础伤害；主动究极技通常使用约 8–10 秒冷却、约 280–340 基础伤害。这里只是起始范围，必须说明偏离原因，并考虑升级倍率。
4. **搜集素材**：优先使用可直接下载、可追溯、允许再分发或明确属于公共领域/自制的来源。图片、GIF、视频、音效分别记录；不能把搜索结果页当成素材授权证明。
5. **登记资源**：把实际文件放入 `assets/images/`、`assets/sounds/` 或项目约定的目录，并在 `assets/sources/manifest.json` 记录 `source`、`file`、`character`、`license`、`retrievedAt`、`status`。未确认授权的资源标记 `status: "review-required"`，不得默认宣传或分发。
6. **接入角色**：把角色对象加入 `window.MEME_DATA.heroes`。使用动态遍历，不新增角色数量硬编码。没有素材时保留 `imagePath`，依靠内置图形和合成音效降级。
7. **验证**：运行 `npm test`；至少启动一次角色的 headless 对局或现有模拟路径，确认角色能被抽卡、存档初始化、配装和战斗创建。

## 素材渠道优先级

按风险从低到高选择：

1. 自制素材、用户明确提供且允许项目使用的素材；
2. 公共领域或明确开放许可证素材库；
3. 官方公开媒体包/官方账号明确允许转载的素材；
4. 仅用于本地试玩的第三方梗图、GIF、视频或音效；必须标记未授权风险，不得伪称可分发；
5. 需要登录、绕过访问限制、抓取付费内容或无法确认来源的站点：不使用。

推荐先查素材库和原作者发布页，再查搜索引擎；下载前记录原始 URL、作者、许可证、下载日期、文件哈希和处理方式。视频只在确有必要时保留，优先抽取经过授权的短 GIF/音效，避免把大文件塞进仓库。

## 交付格式

先输出角色卡，再输出资源清单，最后输出代码改动和验证结果。角色卡至少包含：

```text
梗名 / id / 定位
视觉：emoji、主色、立绘与 fallback
被动：名称、触发条件、效果
普通技能：名称、effectKind、伤害、冷却、描述、喊话
究极技：类型、effectKind、伤害、冷却、cut-in 文案
风险：素材授权、现实人物、平台/品牌/版权风险
```

新增角色前检查：`id`、技能 ID、素材文件名不得重复；不把未验证的远程 URL 直接放入运行时代码；不复制现实人物的敏感或贬损信息；不以“来源已记录”替代授权确认。

详细资源渠道、登记字段和审核清单见 [references/resource-channels.md](references/resource-channels.md)。
